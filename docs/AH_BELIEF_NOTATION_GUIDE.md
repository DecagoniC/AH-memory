# Методичка: что значит \(b_i(\tau)=b_{N_i}(1)\)

Разбор нотации для силы ASSOC между факторами. Сначала словами, потом формулы.

Связанные: [FACTOR_GRAPH_ACTIVATION.md](FACTOR_GRAPH_ACTIVATION.md), [AH_HYPERGRAPH_GUIDE.md](AH_HYPERGRAPH_GUIDE.md), [HYPERPARAMS.md](HYPERPARAMS.md).

---

## Одной фразой

\(b_v(1)\) — «насколько мы уверены, что узел \(v\) сейчас **включён**».  
\(b_i(\tau)\) — то же число **для факта \(i\)**, измеренное **на такте \(\tau\)**.  
Писать \(b_{N_i}(1)\) или «среднее по актантам» — два способа получить это число для гиперребра N.

---

# Часть A. Простым языком

## A1. У каждого узла есть выключатель

В фактор-графе у символа (например `M_ЗАЯЦ`) есть случайная переменная:

- \(X = 0\) — «выключен / не в фокусе»
- \(X = 1\) — «включён / в фокусе»

После belief propagation алгоритм не говорит «точно 0 или 1», а даёт **вероятности**:

| Запись | Читается как |
|--------|----------------|
| \(b(0)\) | вероятность «выключен» |
| \(b(1)\) | вероятность «включён» |
| \(b(0)+b(1)=1\) | нормализация |

Нас почти всегда интересует только **\(b(1)\)** — «насколько ярко горит».  
В коде это и есть активация: `x = b(1)`.

## A2. Индекс у \(b\) — *чей* выключатель

Пишем \(b_v(1)\):

- нижний индекс \(v\) — **UID узла** (`ЗАЯЦ`, `M_ЛЕС`, …);
- \((1)\) — состояние «включён», не «единица как сила».

Примеры:

| Запись | Смысл |
|--------|--------|
| \(b_{\mathrm{M\_ЗАЯЦ}}(1)\) | насколько активен концепт зайца |
| \(b_{\mathrm{ЛЕС}}(1)\) | насколько активна карточка слова «лес» |
| \(b_v(0)\) | насколько верим, что \(v\) **не** активен |

Ошибка чтения: \(b(1)\) ≠ «belief номер один». Это belief **для значения X=1**.

## A3. Такт \(\tau\) — кадр фильма

Память живёт тактами: \(\tau = 0, 1, 2, \ldots\) (в коде `ah.tau`).  
На каждом такте заново крутят BP → у каждого узла **новое** \(b(1)\).

Поэтому пишут зависимость от времени:

\[
b_v(\tau) \quad\text{сокращение для}\quad b_v^{(\tau)}(1)
\]

Читать: «яркость узла \(v\) **на такте \(\tau\)**» (всегда имеется в виду состояние «включён»).

| Запись | Смысл |
|--------|--------|
| \(b_{\mathrm{M\_ЗАЯЦ}}(5)\) | яркость зайца на 5-м такте |
| \(b_i(\tau)\) | яркость объекта \(i\) на такте \(\tau\) |

## A4. Факт N — не такой же узел, как m

Факт вроде `N_LIVE_IN(ЗАЯЦ, ЛЕС)` в BP v1 **часто не имеет своей** переменной \(X_N\).  
Переменные есть у **актантов**: `M_ЗАЯЦ`, `M_ЛЕС`.  
У факта есть **фактор** \(f_N\) (функция совместимости), а «яркость факта» в коде берут **прокси**:

```text
x_N ≈ среднее b(1) по актантам N
```

То есть: «факт горит ярко, если ярко горят его участники».

Отсюда два варианта в той фразе, которая была непонятна:

1. **Если** у факта заведена своя переменная \(X_{N_i}\) → берём \(b_{N_i}(1)\).  
2. **Как сейчас в прототипе** → берём среднее \(b(1)\) актантов и **называем** это \(b_i(\tau)\).

## A5. Что означала спорная строка

> Пусть \(b_i(\tau)=b_{N_i}(1)\) (или mean beliefs актантов N — как сейчас для \(x_N\)).

Разбор по кускам:

| Кусок | Перевод |
|-------|---------|
| \(i\) | номер/индекс **факта** (первого, второго, …) |
| \(N_i\) | сам гиперреберный факт с индексом \(i\) |
| \(b_{N_i}(1)\) | «belief, что факт \(N_i\) включён» — идеальная запись |
| \(b_i(\tau)\) | короткая кличка той же яркости **на такте \(\tau\)** |
| «или mean…» | в коде вместо отдельной \(X_{N_i}\) берут среднее по ролям |
| «как сейчас для \(x_N\)» | в `IgnitionEngine` уже так пишут \(x\) у гиперребра |

**Одной картинкой:**

```text
такт τ
  BP → b_M_ЗАЯЦ(1), b_M_ЛЕС(1), …
  для факта N_i = LIVE_IN(ЗАЯЦ, ЛЕС):
       b_i(τ)  :=  среднее этих b(1)   ← рабочее определение
  (в идеале было бы b_{N_i}(1), если X_N есть)
```

## A6. Зачем это для ASSOC между факторами

Связь «факт ↔ факт» хочет знать: **горели ли два факта рядом по времени**.

- \(b_i(\tau)\), \(b_j(\tau)\) — яркости двух фактов на одном кадре;  
- произведение \(b_i(\tau)\,b_j(\tau)\) — «оба яркие одновременно»;  
- \(\Delta\tau\) между моментами, когда каждый перешагнул порог — «насколько вспышки разъехались по тактам».

Без расшифровки \(b_i(\tau)\) формула силы связи читается как абракадабра.

## A7. Мини-пример числами

Факт \(N_1\): LIVE_IN(ЗАЯЦ, ЛЕС). Актанты: `M_ЗАЯЦ`, `M_ЛЕС`.

На такте \(\tau=3\) после BP:

| Узел | \(b(1)\) |
|------|----------|
| M_ЗАЯЦ | 0.80 |
| M_ЛЕС | 0.70 |

Тогда рабочее:

\[
b_1(3)=\frac{0.80+0.70}{2}=0.75
\]

Факт \(N_2\) на том же такте дал \(b_2(3)=0.60\).  
Совместность: \(0.75\times 0.60=0.45\) — оба заметно активны → кандидат усилить ASSOC(\(N_1\), \(N_2\)).

Если \(N_2\) перешёл порог только на \(\tau=10\), а \(N_1\) — на \(\tau=3\), то \(\Delta\tau=7\) — временной штраф \(e^{-\Delta\tau/\tau_0}\) уменьшит прирост веса.

# Часть B. Математика (аккуратно)

## B1. Belief одной переменной

После (loopy) BP для \(X_v\in\{0,1\}\):

\[
b_v(x)\;\approx\;P(X_v=x\mid \text{evidence}),\qquad x\in\{0,1\}
\]

\[
b_v(0)+b_v(1)=1,\qquad x_v:=b_v(1)
\]

WM: \(v\in\mathrm{WM} \iff b_v(1)>t\).

## B2. Зависимость от такта

Такт \(\tau\in\mathbb{N}\). На каждом \(\tau\) пересчитывают сообщения → новый \(b_v^{(\tau)}\).

**Соглашение сокращения** (как в прошлом ответе):

\[
b_v(\tau)\;\stackrel{\mathrm{def}}{=}\;b_v^{(\tau)}(1)
\]

То есть аргумент \(\tau\) в \(b_v(\tau)\) — **время**, а не значение переменной.  
Значение «включён» уже зашито в сокращение.

Если нужно явно и то и другое:

\[
b_v^{(\tau)}(1)\quad\text{или}\quad b_v(X_v=1;\tau)
\]

## B3. Два определения «яркости факта»

Пусть факт \(N_i\) имеет актантов с UID \(v\in\partial N_i\) (роли SUBJECT, OBJECT, …).

**Определение A (идеальное, если есть \(X_{N_i}\)):**

\[
b_i(\tau)\;=\;b_{N_i}^{(\tau)}(1)
\]

**Определение B (прототип сейчас):**

\[
b_i(\tau)\;=\;\frac{1}{|\partial N_i|}\sum_{v\in\partial N_i} b_v^{(\tau)}(1)
\]

Именно B совпадает с тем, как в ignition пишут \(x_N\) = mean belief актантов.

Можно брать max вместо mean — жёстче к «хотя бы один актант»; mean мягче к «вся сцена».

## B4. Запись \(b_i(\tau)=b_{N_i}(1)\) — что это за равенство

Это **не теорема**, а **обозначение**:

> «Под символом \(b_i(\tau)\) будем понимать яркость факта \(i\) на такте \(\tau\); в идеале это \(b_{N_i}(1)\) на этом такте; на практике — mean по актантам.»

Скобка «или mean…» как раз предупреждает: в коде \(X_{N_i}\) может не быть.

## B5. Связь с силой ASSOC(\(N_i\), \(N_j\))

Онлайн-обновление (схема):

\[
\Delta w_{ij}
=\eta\cdot b_i(\tau)\cdot b_j(\tau)\cdot e^{-|\tau_i^{\mathrm{last}}-\tau_j^{\mathrm{last}}|/\tau_0}
\]

где \(\tau_k^{\mathrm{last}}\) — последний такт с \(b_k(\tau)>t\).

Здесь уже все символы расшифрованы:

| Символ | Смысл |
|--------|--------|
| \(b_i(\tau)\) | яркость факта \(i\) на текущем такте (def. A или B) |
| \(b_j(\tau)\) | то же для \(j\) |
| \(\eta\) | скорость обучения Hebb |
| \(\tau_0\) | на сколько тактов «близко» ещё считается близко |
| \(w_{ij}\) | вес ASSOC между факторами |

## B6. Частые путаницы

| Путают | Как правильно |
|--------|----------------|
| \(b(1)\) = «первый belief» | belief для **состояния** \(X=1\) |
| \(b_i\) и \(b_{N_i}\) — разное | \(i\) — индекс; \(N_i\) — сам факт; \(b_i\) — кличка яркости |
| \(b_v(\tau)\) — \(\tau\) это 0/1 | в сокращении \(\tau\) — **номер такта** |
| факт всегда имеет \(X_N\) | в v1 часто нет; есть \(f_N\) и прокси mean |
| \(x_N\) и \(b_i(\tau)\) | для факта по def. B это одно и то же на данном такте |

# Шпаргалка

```text
X_v ∈ {0,1}     — выключатель узла v
b_v(1)          — насколько «включён» (это и есть x_v)
b_v(τ)          — то же на такте τ   [= b_v^(τ)(1)]
b_i(τ)          — яркость факта i на такте τ
                = b_{N_i}(1)        если есть переменная факта
                = mean_актантов b(1)  как в прототипе сейчас
```

```text
ASSOC сила между фактами ← насколько оба яркие и насколько их вспышки близки по τ
```
