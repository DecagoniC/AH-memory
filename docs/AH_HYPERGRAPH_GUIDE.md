# Методичка: гиперграф АГ-памяти

Сначала аналогии простым языком, затем формализм. Опора: монография Душкина + реализация AH-memory.

Источник: canvas `ah-hypergraph-guide.canvas.tsx`.

Связанные документы: [DOMAIN.md](DOMAIN.md), [FACTOR_GRAPH_ACTIVATION.md](FACTOR_GRAPH_ACTIVATION.md), [AH_AS_FACTOR_GRAPH.md](AH_AS_FACTOR_GRAPH.md).

Теги: `AH = ⟨S, C, P, H, L⟩` · гиперграф · 1° / 2°

---

## Одной фразой

AH — это не одно дерево и не три пересекающихся множества «одних и тех же» узлов, а словарь ярлыков **S** плюс три равноправные полки фактов **C / P / H** и общий ящик бинарных рёбер **L**. Факты с несколькими участниками — гиперрёбра **N** внутри полок.

---

# Часть A. Простым языком

## A1. Аналогия: библиотека + записные книжки

| Кусок AH | Аналогия |
|----------|----------|
| **S** — каталожная карточка | Слово «заяц» на карточке, склонения, иногда картинка/звук. Карточка сама по себе не рассказ. |
| **C / P / H** — три тетради | Учебник (общее), «мой заяц во дворе» (частное), дневник «что было сегодня» (история). Формат записи один и тот же. |
| **N** — предложение в тетради | «Заяц обитает в лесу» — одна запись с ролями кто/где. Гиперребро: сразу несколько участников. |
| **L** — скрепки и стрелки | Скрепка карточки «ЗАЯЦ» к `M_ЗАЯЦ`; стрелка «заяц — это зверёк»; стрелка «потом случилось вот это». |

## A2. Равноправны ли C, P, H?

**Да, структурно равноправны.** С точки зрения типов элементов это три одинаковые гиперсети: в каждой могут лежать `m`, `N`, `T`, `k`, `g`. Они не «уровни власти», а разные полки по смыслу срока/роли знания.

| Вопрос | Ответ |
|--------|--------|
| Пересекаются ли C∩P∩H по одному и тому же UID? | Нет: один элемент лежит ровно в одной полке (в реализации UID уникален в C∪P∪H∪S) |
| Могут ли полки быть связаны? | Да — рёбрами L и тем, что N в H ссылается на m, который лежит в C |
| Один смысл — два узла? | Да: `M_ЗАЯЦ` ∈ C (класс) и `M_этот_заяц` ∈ P (экземпляр), связаны IS-A / фактами |
| Что общее у полок? | Одинаковый «формат бумаги»; разный контент и политика жизни (TTL у H жёстче) |

### Схема полок

```text
┌─────────────────────────────────────────────────────────────┐
│ S — словарь ярлыков (не «полка фактов»)                     │
│ ЗАЯЦ · СЕРГЕЙ · МОСКВА · ЛЕС  +  словоформы / модальности R │
└─────────────────────────────────────────────────────────────┘

┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ C — общее    │  │ P — частное  │  │ H — история  │
│ M_ЗАЯЦ, T_IS │  │ M_этот_заяц  │  │ M_Я,         │
│ N фактов     │  │ частные N    │  │ N_LIVE_IN,   │
│ курса        │  │              │  │ k_EP_…       │
│ «учебник»    │  │ экземпляры   │  │ эпизоды      │
└──────────────┘  └──────────────┘  └──────────────┘
   равноправные гиперсети · элемент лежит в одной полке

┌─────────────────────────────────────────────────────────────┐
│ L — все бинарные рёбра (ASSOC, IS-A, FOLLOW, …)             │
│ могут соединять S↔m, m↔m, в т.ч. концы из разных полок      │
└─────────────────────────────────────────────────────────────┘
```

## A3. Что такое s и какие бывают «разновидности»

`s ∈ S` — абстракт 1°. В полной модели к нему привязаны первичные сенсорные символы по модальностям. В прототипе AH-memory почти всегда модальность TEXT (словоформы).

| Разновидность / срез | Что это | Пример |
|----------------------|---------|--------|
| ЕЯ-ярлык | UID понятия словами | ЗАЯЦ, СЕРГЕЙ, МОСКВА |
| R[TEXT] | словоформы / написания | заяц, зайца, зайцу |
| R[VISION] и др. | сенсорные привязки (монография) | образ куба, звук … |
| Предикатный ярлык | имя отношения в S | часто через T.predicate → IS, LIVE_IN |

«Разновидности s» — не разные классы в коде, а разная начинка R и роль UID. Математически все \(s = \langle UID, R \rangle\).

## A4. Приставка M_ — зачем и у кого

**Это соглашение проекта.** В монографии UID может быть любым. В AH-memory префикс `M_` помечает символ 2° (m), чтобы глазами отличать от ярлыка в S.

| Есть `M_` | Нет `M_` |
|-----------|----------|
| `M_Я`, `M_ЗАЯЦ`, `M_МОСКВА`, `M_СЕРГЕЙ`… | `ЗАЯЦ`, `СЕРГЕЙ` (S) |
| | `N_LIVE_IN_00008`, `T_IS`, `L_BIND_…`, `k_EP_…` |

**Почему не «одно и то же»:** `СЕРГЕЙ` — карточка слова; `M_СЕРГЕЙ` — узел, который ставят в роли SUBJECT/OBJECT и цепляют к фактам. ASSOC bind склеивает карточку и узел, чтобы слово из текста зажигало концепт.

## A5. Схема одного факта

Реплика: «Заяц обитает в лесу.»

| Появляется | Где | Зачем |
|------------|-----|--------|
| ЗАЯЦ, ЛЕС | S | ярлыки + словоформы |
| M_ЗАЯЦ, M_ЛЕС | C (или H в диалоге) | актанты |
| T_LIVE_IN | C | схема ролей SUBJECT/LOCATION |
| N_LIVE_IN_… | C/H | факт: SUBJECT→M_ЗАЯЦ, LOCATION→M_ЛЕС |
| ASSOC bind ×2 | L | M_ЗАЯЦ↔ЗАЯЦ, M_ЛЕС↔ЛЕС |
| ASSOC mesh (опц.) | L | M_ЗАЯЦ↔M_ЛЕС |

# Часть B. Математическая подноготная

## B1. Кортеж

```text
AH = ⟨ S, C, P, H, L ⟩

S — множество абстрактов 1°
C, P, H — три АГ-гиперсети (гиперграфы элементов)
L — множество бинарных ассоциативных связей
```

C, P, H как носители элементов в реализации **дизъюнктны по UID**. «Пересечение» — не общая запись в двух множествах, а общие связи/ссылки между элементами разных полок.

## B2. Элементы

Носители гиперграфа. Звёздочка в записи \(e^*\) = ссылка на элемент: \(s^*\) указывает в S, \(m^*\) — на m в C∪P∪H (в коде `SRef` / `MRef`).

```text
s ∈ S:     s = ⟨ UID, R ⟩
m:         m = ⟨ UID, Pr, Mt ⟩
T:         T = ⟨ UID, s_pred*, A ⟩
N:         N = ⟨ UID, w, T*, fillers, Pr, Mt ⟩
l ∈ L:     l = ⟨ UID, id, w, (e1*, e2*) ⟩
k:         k = ⟨ UID, items, Pr, Mt ⟩
g:         g = ⟨ UID, id, operands ⟩   (служебная свёртка, реже в прототипе)
```

### s ∈ S — абстракт 1°

```text
s = ⟨ UID, R ⟩
R : модальность → множество первичных символов / форм
в прототипе:  R[TEXT] = {сергей, сергея, …}
```

- **Поля:** UID — имя ярлыка; R — размеченный набор привязок (текст, в полной модели ещё VISION/AUDIO…). x — возбудимость (для BP).
- **Где:** только множество S (не в C/P/H).
- **Пример:** UID=`СЕРГЕЙ`, R[TEXT]={сергей, сергея}. Не ставят в роль SUBJECT у N напрямую — для этого есть m.

### m — символ 2°

```text
m = ⟨ UID, Pr, Mt ⟩
UID часто = M_ + ярлык   (соглашение кода)
Pr — свойства, Mt — мета-свойства
```

- **Поля:** Pr — обычные свойства (label, …); Mt — служебные/мета. Именно m — типичный актант ролей и конец IS-A / ASSOC mesh.
- **Где:** ровно одна из полок C, P или H.
- **Пример:** `M_ЗАЯЦ` ∈ C с Pr=[label=заяц]; `M_Я` ∈ H из реплики диалога.

### T — шаблон предиката

```text
T = ⟨ UID, s_pred*, A ⟩
A = [ ActantSlot(role, filler?) , … ]
пример: T_IS → roles { SUBJECT, OBJECT }
         T_LIVE_IN → { SUBJECT, LOCATION }
```

- **Смысл:** сигнатура отношения. `s_pred*` — ссылка на ярлык предиката в S. A — упорядоченные слоты ролей; в шаблоне filler обычно пуст.
- **Где:** чаще C. Сам T — не факт и не ребро L.
- **Связь с N:** каждый N ссылается на T* и заполняет A конкретными e*.

### N — гиперсвязь / факт

```text
N = ⟨ UID, w, T*, fillers, Pr, Mt ⟩
fillers : Role → e*     (обычно m*)

пример LIVE_IN:
  T* = T_LIVE_IN
  SUBJECT  → M_ЗАЯЦ
  LOCATION → M_ЛЕС
  w ∈ (0,1] — сила факта (α_N = κ·w в FG)
```

- **Смысл:** одна ситуация = одно гиперребро над актантами. В фактор-графе это \(f_N\).
- **Где:** C (знания), P (частные), H (эпизоды).
- **Не путать:** `N_IS_…` — факт по `T_IS`; **IS-A** — это \(l \in L\), не N.

### l ∈ L — бинарная ассоциативная связь

```text
l = ⟨ UID, id, w, (e1*, e2*) ⟩

id = ASSOC  → симметричная склейка (bind s↔m или mesh m↔m)
id = IS-A   → направленно: e1=child, e2=parent
id = FOLLOW → порядок эпизодов / фактов во времени
```

- **Где:** только множество L. Концы e1*, e2* могут указывать в S или в C∪P∪H.
- **В FG:** фактор \(f_l\); вид потенциала зависит от id.

### k, g — список и функциональный символ

```text
k = ⟨ UID, items, Pr, Mt ⟩
    items = [ e1*, e2*, … ]  — упорядоченные ссылки
    Type ∈ { Hierarchy, Heterarchy, Episode }  (мета, монография)

g = ⟨ UID, id, operands ⟩
    детерминированная свёртка операндов (OR, …) — служебное
```

- **k:** упаковка мета-структуры (таксономия, гетерархия-семья, эпизод диалога). Сами IS-A/FOLLOW лежат в L; k именует и группирует.
- **Пример k:** `k_EP_USER_1` → ссылки на N и m одного хода диалога в H.

### Сводка носителей: что чем является

| Элемент | Что это | Арность / связь | С кем соседствует |
|---------|---------|-----------------|-------------------|
| **s** | Ярлык 1°: имя понятия + формы/сенсоры в R. Карточка слова, не участник факта. | только через L (bind) | обычно m (ASSOC bind) |
| **m** | Символ 2°: рабочий концепт. То, что ставят в роли SUBJECT/OBJECT/… | роли N + рёбра L | другие m, s, концы IS-A / mesh |
| **T** | Сигнатура предиката: какие роли бывают (чертёж факта, не сам факт). | порождает экземпляры N | s_pred (имя отношения), слоты A |
| **N** | Факт = заполненный T: одна ситуация с конкретными актантами и весом w. | n-арное гиперребро (по ролям) | несколько m (fillers) |
| **l** | Бинарное ребро в L: ASSOC / IS-A / FOLLOW между двумя концами e1*, e2*. | ровно 2 | s и/или m (иногда k в FOLLOW) |
| **k** | Именованный список ссылок: упаковка иерархии / гетерархии / эпизода. | группирует, сам не предикат | набор e* (N, m, …) |
| **g** | Служебная функция над операндами (свёртка OR/…). Редко в прототипе. | по числу operands | ссылки e* в operands |

Коротко: **s** — словарь, **m** — смысл, **T** — схема, **N** — утверждение, **l** — парная склейка/стрелка, **k** — папка-список, **g** — калькулятор.

**Как читать B2 на одном факте:** текст «я живу в Москве» → s: Я/МОСКВА (формы) → m: M_Я, M_МОСКВА → T_LIVE_IN задаёт слоты → N заполняет fillers → L (bind/mesh) склеивает пары. Всё это разные типы элементов, не разные «копии» одного UID в двух полках.

## B3. Гиперграф

Вершины — символы (s, m, …) и при желании сами N как элементы. Гиперребро N инцидентно нескольким m через роли. Бинарные рёбра L — обычные 2-рёбра поверх того же множества вершин (включая концы в S).

```text
Вершины V ⊇ S ∪ { m, N, T, k, … ∈ C∪P∪H }

Гиперрёбра:  каждое N задаёт e_N ⊆ V  (актанты по ролям)
Бинарные:    каждое l ∈ L — ребро {e1, e2} с меткой id
```

## B4. Иерархия vs гетерархия (мета-структуры)

| Мета-объект | Условие | Где типично |
|-------------|---------|-------------|
| Иерархия | DAG связей с одним id (часто IS-A) | C, P |
| Гетерархия | связный подграф, id связей любые | C, P (+ весь граф) |
| Эпизод | DAG с FOLLOW по фактам/спискам | H |

\[
\mathrm{Episode} \subset \mathrm{Hierarchy} \subset \mathrm{Heterarchy}
\]

(монография, рис. 12)

## B5. Связь с фактор-графом активации

```text
Переменные:   X_v ∈ {0,1},  v ∈ S ∪ {m …}
Факторы:      f_N  (гиперребро-факт)
              f_l  (ASSOC / IS-A / FOLLOW)
              f^obs, f^prior  (вход / затухание)

P(X) ∝ ∏_N f_N · ∏_l f_l · ∏_v f^obs · ∏_v f^prior
x_v := b_v(1)   после loopy BP
```

Секция C/P/H не меняет вид потенциала: меняет, какие узлы вообще существуют и как долго живут. Тип связи (N vs ASSOC vs IS-A) задаёт вид фактора.

## B6. Мини-пример числами (ASSOC bind)

\(l\): ASSOC(M_СЕРГЕЙ, СЕРГЕЙ), \(w=1\), \(\gamma\approx 1\) → \(f = \exp(X_M \cdot X_S)\). Конфиг (1,1) усиливается; (1,0) нейтрален. Поэтому зажигание ярлыка из текста подтягивает m через BP.

# Шпаргалка

| | |
|--|--|
| **S** | ярлыки 1° |
| **M_** | соглашение для m |
| **C = P = H** | формат полок равен |
| **L + N** | рёбра + гиперфакты |

| Путаница | Как правильно |
|----------|----------------|
| C/P/H пересекаются одними UID | UID в одной полке; связи между полками через L/N |
| M_ обязателен математикой | удобный префикс реализации для m |
| Всё — иерархия | таксономия IS-A — частный случай; граф в целом гетерархичен |
| ASSOC = факт | факт — N; ASSOC — парная склейка |
