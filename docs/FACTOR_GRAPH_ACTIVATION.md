# АГ-память как фактор-граф: математический аппарат

Документ фиксирует формализацию наложения фактор-графов (теория вероятностей / graphical models) на ассоциативно-гетерархическую память (АГ-память, монография Душкина) и замены тактового механизма фокуса активации (§8) на вероятностный message passing.

Статус: **спецификация v1** — реализовано в `factor_graph.py`, `belief_propagation.py`, `IgnitionEngine` (BP).  
Связанные документы: [DOMAIN.md](DOMAIN.md), [INTERFACES.md](INTERFACES.md), [HYPERPARAMS.md](HYPERPARAMS.md).

---

## 1. Мотивация

Текущий Ignition Engine оперирует скалярной возбудимостью xₑ ∈ [0, 1] и эвристической суммой z = Σ f·w по ассоциативным связям и гиперсвязям. Это активационный, **не нормированный** процесс.

Гиперсвязь N в АГ-памяти уже имеет семантику **мультиарного отношения** (предикат + роли актантов). В терминах фактор-графов это естественно соответствует **фактору** над переменными-актантами, а не «ещё одной вершине той же природы».

Цель формализации:

1. сохранить кортеж AH = ⟨S, C, P, H, L⟩ и типы элементов;
2. дать вероятностную семантику активации / фокуса / трассировки;
3. заменить такт воспламенения на (приближённый) loopy belief propagation;
4. оставить БЯМ модулем evidence (экстракция фактов), а не источником маргиналов.

---

## 2. Базовые объекты АГ-памяти (напоминание)

| Объект | Смысл |
|--------|--------|
| s ∈ S | абстрактный символ 1-го порядка ⟨UID, R⟩ |
| m | абстрактный символ 2-го порядка в C ∪ P ∪ H |
| T | шаблон модели управления предиката |
| N | гиперсвязь — заполненный экземпляр шаблона (факт) |
| l ∈ L | бинарная ассоциативная связь ⟨UID, ID, w, (e₁*, e₂*)⟩ |
| g, k | функциональный символ / список (служебные конструкции) |

Текущая активация: xₑ, веса w, затухание g, порог t, Hebb h, pacemaker ν.

---

## 3. Фактор-граф: определения

Фактор-граф — двудольный граф:

- **переменные** Xᵢ (variable nodes);
- **факторы** fₐ(X_∂a) (factor nodes) — неотрицательные функции на подмножестве переменных, инцидентных фактору a;
- рёбра только между переменной и фактором, если переменная входит в область фактора.

Совместное распределение (до нормировки):

```
P(X) ∝ ∏_a fₐ(X_∂a)
```

Вывод:

- **sum-product** — маргиналы P(Xᵢ), мягкий фокус;
- **max-product** — MAP-конфигурация, жёсткая цепочка для объяснимости.

На графах с циклами используется **loopy BP** с damping (приближение).

## 4. Отображение AH → фактор-граф

### 4.1. Переменные (v1)

Для версии 1:

```
Xᵥ ∈ {0, 1},   v ∈ S ∪ { m | m — символ 2-го порядка }
```

Интерпретация: Xᵥ = 1 — «символ в фокусе / активен».

Скаляр активации отождествляется с belief:

```
xᵥ ≡ bᵥ(1) ≈ P(Xᵥ = 1 | evidence)
```

**Не являются переменными в v1:**

| Объект | Роль в FG |
|--------|-----------|
| T | схема / семейство потенциалов ψ_π, не узел-переменная |
| g | детерминированная свёртка операндов (OR, VERY, …) |
| k | именованная группа ссылок на переменные |

### 4.2. Факторы

#### A. Предикатный фактор (гиперсвязь N)

Каждый N с предикатом π и заполнением ролей r ↦ vᵣ:

```
f_N(X_{vᵣ} : r ∈ dom(N)) = ψ_π( (X_{vᵣ})_r ; θ_N )
```

Минимальная параметризация v1 (совместная активация актантов):

```
ψ_π = exp( α_N · ∏_r X_{vᵣ}  +  Σ_r β_{N,r} · X_{vᵣ} )
```

Связь с текущим весом гиперсвязи:

```
α_N = κ · w_N
  или
α_N = logit(w_N)

(κ > 0 — гиперпараметр)
```

Коэффициенты β_{N,r} допускают асимметрию ролей (SUBJECT/OBJECT весомее LOCATION и т.д.).

#### B. Бинарный фактор из l ∈ L

Для связи l = (e₁, e₂) типа id ∈ {IS-A, FOLLOW, ASSOC, …}:

```
f_l(X_{e₁}, X_{e₂}) = exp( γ_id · w_l · φ_id(X_{e₁}, X_{e₂}) )
```

Рекомендуемые φ_id (v1):

| id | φ_id | Смысл |
|----|------|--------|
| IS-A | штраф за X_child·(1 − X_parent); поощряется X_child ⇒ X_parent | направленное обобщение |
| ASSOC | X_{e₁}·X_{e₂} (симметрично) | привязка m ↔ s |
| FOLLOW | мягкая согласованность соседних эпизодов | траектория, не таксономия |

**Важно:** IS-A не сводить к симметричному потенциалу — иначе размывается направление обобщение/конкретизация (кейс «собака», §8 монографии).

#### C. Унарные evidence-факторы (восприятие)

Perception (БЯМ / rules) по тексту задаёт множество seed-UID. Для каждого такого v:

```
fᵥ^obs(Xᵥ) = { e^λ,  если Xᵥ = 1
              { 1,    если Xᵥ = 0
```

где λ > 0 — сила сенсорной подпитки (аналог прежнего δ в seed).

#### D. Унарный prior (замена затухания)

```
fᵥ^prior(Xᵥ) = { ε,  если Xᵥ = 1
               { 1,  если Xᵥ = 0

0 < ε ≪ 1
```

Без evidence маргинали сжимаются к малой вероятности фокуса — аналог сенсорной депривации и функции g.

#### E. Шаблон T

T = ⟨UID, s*, A⟩ задаёт **семейство** потенциалов {ψ_π}.  
Конкретный N — экземпляр с зафиксированными аргументами-актантами.

### 4.3. Совместное распределение на АГ-памяти

```
P(X) ∝  ∏_N f_N(X_∂N)
      · ∏_{l ∈ L} f_l(X_∂l)
      · ∏_v fᵥ^obs(Xᵥ)
      · ∏_v fᵥ^prior(Xᵥ)
```

## 5. Message passing как такт воспламенения

### 5.1. Двудольная структура

```text
  переменные:  s ∈ S,  m ∈ C ∪ P ∪ H
        |
        |  инцидентность (роль / конец связи / evidence)
        |
  факторы:     N,  f_l (из L),  f^obs,  f^prior
```

### 5.2. Сообщения (sum-product, бинарный носитель)

Обозначения: a — фактор, v — переменная, xᵥ ∈ {0, 1}.

**Переменная → фактор:**

```
m_{v→a}(xᵥ) ∝ fᵥ^obs(xᵥ) · fᵥ^prior(xᵥ) · ∏_{a'∋v, a'≠a} m_{a'→v}(xᵥ)
```

**Фактор → переменная:**

```
m_{a→v}(xᵥ) ∝ Σ_{X_{∂a \ {v}}}  f_a(X_∂a) · ∏_{u ∈ ∂a \ {v}} m_{u→a}(x_u)
```

**Belief:**

```
bᵥ(xᵥ) ∝ fᵥ^obs(xᵥ) · fᵥ^prior(xᵥ) · ∏_{a∋v} m_{a→v}(xᵥ)
```

Нормировка: bᵥ(0) + bᵥ(1) = 1.

### 5.3. Определение такта

**Один такт фокуса активации** := k раундов damped loopy BP (по умолчанию k = 1 или малое фиксированное k под бюджет ≤ 500 ms на графе размера ≈ 1000).

Damping:

```
m^{(τ+1)} ← (1 − δ) · m^new + δ · m^{(τ)},   δ ∈ (0, 1)
```

Pacemaker ν: периодическое добавление слабого стационарного унарного импульса / dithering, чтобы сообщения не вырождались в нули при отсутствии входа.

### 5.4. Рабочая память (GWT)

```
WM = { v | bᵥ(1) > t }
```

Альтернатива (режим QA): top-k по bᵥ(1).

### 5.5. Трассировка (explainability, метрика M2)

Пусть Δ_{a→v} — нормированный вклад фактора a в обновление bᵥ на последних раундах (например, изменение лог-отношения сообщений).

```
Trace = { a | ∃ v ∈ WM: Δ_{a→v} > ε_tr }
```

Ответ агента строится **только** из фактов/N и связей, попавших в Trace (или из переменных WM с восстановлением инцидентных факторов). БЯМ не имеет права добавлять факты вне Trace.

## 6. Соответствие старым гиперпараметрам §8

| № | Было | Стало в FG-семантике |
|---|------|----------------------|
| 1 | TTL жизни элемента | без изменений (GC); не часть P(X) |
| 2 | затухание g | prior f^prior + отсутствие evidence |
| 3 | порог t | порог на bᵥ(1) для WM |
| 4 | Hebb h | обновление параметров θ (см. §7) |
| 5 | частота ν | периодический слабый prior / dithering |
| — | seed δ | сила evidence λ |
| — | активация f | ядро sum-product в лог-домене |

Рекомендуется вести расчёты в **лог-домене** для численной устойчивости.

## 7. Обновление параметров (вместо сырого Hebb)

Обозначим b_u = b_u(1).

**Pairwise (связи L):**

```
w_l ← clip( w_l + η · 𝟙[b_{e₁} · b_{e₂} > τ_H] ,  0, 1 )
```

**Фактор N:**

```
α_N ← α_N + η_N · 𝟙[ ∏_r b_{vᵣ} > τ_H ]
```

с последующим отображением α_N ↦ w_N ∈ [0, 1].

Строгий вариант (этап 2): градиент псевдоправдоподобия по наблюдаемым фактам корпуса / диалога.

## 8. Согласование с Global Workspace / ignition

В вероятностной семантике «воспламенение» — не перенос узла по порогу энергии, а:

1. фиксация унарных evidence-факторов от текста;
2. несколько раундов MP → концентрация вероятностной массы на коалиции переменных;
3. WM = носитель высокой массы (коалиция в фокусе);
4. ответ и explainability — из факторов, реально внёсших вклад в beliefs.

Устойчивые «петли возбуждения» интерпретируются как приближённые моды на циклах (IS-A + факты) при damping.

## 9. Зафиксированные решения v1

1. **N — только фактор**, не отдельная RV «факт истинен».  
   (Вариант B с Z_N ∈ {0, 1} отложен: ближе к «гиперсвязь и узел, и ребро», но усложняет MP.)

2. **Переменные** — бинарные Xᵥ ∈ {0, 1} для s и m.

3. **Фокус / WM** — sum-product beliefs bᵥ(1).

4. **QA / цепочки объяснения** — допускается отдельный режим max-product + traceback по факторам.

5. **IS-A** — направленный soft-потенциал (потомок ⇒ предок).

6. **БЯМ** — только evidence / парсер / NLG по Trace; не источник маргиналов.

7. **Один контур активации** — xᵥ := bᵥ(1); параллельная эвристическая сумма z = Σ f·w не сохраняется.

---

## 10. Явно не смешивать

1. Не назначать каждому N одновременно статус переменной и фактора без введения Z_N.
2. Не использовать один потенциал для IS-A и FOLLOW.
3. Не подменять маргиналы генерацией БЯМ (обход графа → обнуление M2).
4. Не интерпретировать текущий UI-дамп «как направленный граф» как фактор-граф: визуализация должна различать variable nodes и factor nodes (N).

---

## 11. Аксиоматика ядра (кратко)

1. Xᵥ ∈ {0, 1} для символов s, m.
2. Каждый N → f_N, w_N ↦ α_N.
3. Каждый l ∈ L → f_l с типом id.
4. Perception → f^obs.
5. Такт = damped loopy BP (sum-product); xᵥ := bᵥ(1).
6. WM = { v | bᵥ(1) > t }.
7. Trace = факторы с вкладом > ε_tr в beliefs WM.
8. Prior + damping заменяют g и частично ν.

## 12. Открытые параметры (калибровка, не смена аппарата)

| Символ | Смысл | Старт (черновик) |
|--------|--------|------------------|
| κ | масштаб w_N → α_N | 1 … 3 |
| λ | сила evidence | 2 … 4 |
| ε | prior на X = 1 | 10⁻² … 10⁻¹ |
| δ | damping BP | 0.3 … 0.5 |
| t | порог WM | 0.55 (как в HYPERPARAMS) |
| k | раундов BP на такт | 1 … 3 |
| ε_tr | порог вклада в Trace | 10⁻³ … 10⁻² |
| η, τ_H | Hebb в пространстве θ | как прежние η, с порогом на beliefs |
