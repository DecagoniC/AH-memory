# Гиперпараметры Ignition (черновик)

Источник: монография §8, с. 52–53; постановка §4.3.

| № | Имя | Обозначение | Стартовое значение | Обоснование |
|---|-----|-------------|-------------------|-------------|
| 1 | Время первоначальной жизни | `TTL` (L) | **32 такта** | Новый узел должен успеть получить ≥1 связь после ingest (парсер + Transform + addLink). 32 ≈ запас для асинхронной сборки факта и короткой волны активации. Тестируется M3: в TTL GC не трогает узел. |
| 2 | Функция затухания | `g` | `x ← x · exp(−λ·Δt)`, `λ=0.15`, `Δt=1` | Экспонента из постановки. `λ=0.15` даёт ~половинное затухание за ~4.6 такта — контекст в WM держится несколько тактов, но гаснет без подпитки (сенсорная депривация). |
| 3 | Порог рабочей памяти | `t` | **0.55** | При сигмоидной/насыщенной активации и начальных `w∈[0.3,0.8]` порог отсекает слабый шум, оставляя коалиции 5–30 узлов на графе N≈1000 (ориентир для демо). |
| 4 | Актуализация весов | `h` | `w ← clip(w + η·x_out·x_in, 0, 1)`, `η=0.05` | Правило Хебба из постановки. Малый `η` стабилизирует граф на длинных прогонах; clip сохраняет `w∈[0,1]` для GC (нулевые веса → кандидаты в orphan). |
| 5 | Частота водителя ритма | `ν` | **1 импульс / 8 тактов** | Без сенсорного входа активность не должна полностью умирать между репликами диалога; слишком частый pacemaker размывает фокус. 1/8 — компромисс для QA-цикла. |

## Factor-graph BP (дополнение)

| Имя | Поле | Старт |
|-----|------|-------|
| κ | `fg_kappa` | 2.0 |
| λ evidence | `fg_lambda` | 3.0 |
| ε prior | `fg_epsilon` | 0.05 |
| damping | `fg_damp` | 0.4 |
| раунды/такт | `fg_rounds` | 2 |
| ε_tr | `fg_trace_eps` | 1e-3 |
| τ_H Hebb | `fg_hebb_tau` | 0.15 |

Belief и activation теперь разделены. Сообщения BP формируют входной
сигнал `z_v`, затем выбранная `ActivationFunction` обновляет
`x_v^{t+1}=G(x_v^t,z_v^t,e_v^t)`.

## ExperimentConfig

| Группа | Основные параметры |
|--------|---------------------|
| activation | `type`, `alpha`, `beta`, `gamma`, `decay`, `eta` |
| factors | `is_a_up/down`, `follow_forward/backward`, `association`, `bind`, `hypernode_mode` |
| inference | `max_ticks`, `threshold`, `convergence_epsilon`, `factor_evaluation`, `exact_max_arity` |
| competition | `enabled`, `type`, `strength`, `top_k` |

Значения находятся в `config.yaml:experiment`. Они являются стартовыми
точками grid search, а не утверждением о правильности модели.

## Вспомогательные функции (не в пятёрке, но фиксируются)

| Имя | Значение | Заметка |
|-----|----------|---------|
| `f` (активация) | `σ(z) = 1/(1+e^(−z))` с выходом на ребро `f·w` как в §8 | Сигмоида ограничена (0,1), удобна для порога `t`. Альтернатива ReLU+sat — если бенчмарк такта упрётся в perf. |
| Начальный `x` при seed | `min(1.0, x + δ)`, `δ=0.8` для символов из Perception | Сильная подпитка сенсора, как в кейсе «собака». |
| Начальный `w` новой связи | `0.5` | Нейтральный старт до Hebb. |

## План калибровки на защите

1. Показать baseline-трассу на кейсе «заяц» / «собака».
2. Увеличить `λ` → быстрее гаснет WM.
3. Уменьшить `t` → шире фокус, больше шума в ответе.
4. Увеличить `η` → быстрее «залипание» ассоциаций.
5. Выключить pacemaker (`ν=0`) при отсутствии входа → полный коллапс активности.
