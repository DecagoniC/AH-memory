AH-memory: тесты и метрики
математическая / архитектурная / алгоритмическая точки зрения
================================================================================
Контекст:
  - монография Р.В. Душкина «Ассоциативно-гетерархическая память» (2026), PDF
  - спецификация фактор-графа: docs/FACTOR_GRAPH_ACTIVATION.md
  - гиперпараметры: docs/HYPERPARAMS.md
  - контракты: docs/INTERFACES.md

Обозначения:
  AH = ⟨S, C, P, H, L⟩
  x_v ≡ b_v(1) ≈ P(X_v=1 | evidence)     (v1: binary RV)
  WM = { v | b_v(1) > t }
  Trace = { a | ∃v∈WM: Δ_{a→v} > ε_tr }
  N — гиперсвязь (факт) = фактор; l ∈ L — бинарный фактор
  τ — глобальный такт; k — раундов damped loopy BP на такт

Пороги ниже — рекомендуемые для регрессии / защиты; калибруются на корпусе.

1. МАТЕМАТИЧЕСКИЕ ТЕСТЫ (структура AH + фактор-граф)
================================================================================

--------------------------------------------------------------------------------
T-MATH-01  Кортеж AH замкнут по типам
--------------------------------------------------------------------------------
Цель:    каждый элемент принадлежит ровно одной из секций S|C|P|H|L
         (N,m ∈ C∪P∪H; s ∈ S; l ∈ L).
Вход:    любой валидный dump / rabbit / encyclopedia.
Проверка:
  - uid уникальны в объединении hyper∪S∪L
  - Section(e) ∈ {C,P,H} для всех hypernodes
  - нет «висящих» объектов вне кортежа
Метрика: M-INV = 1 − (#violations / #elements); PASS iff M-INV = 1.0
Связь с монографией: §3 определение AH = ⟨S,C,P,H,L⟩

--------------------------------------------------------------------------------
T-MATH-02  IS-A — ориентированный ациклический граф (иерархия)
--------------------------------------------------------------------------------
Цель:    иерархия по LinkId.IS_A — DAG.
Метод:   DFS / topological sort на рёбрах iter_is_a_edges.
Проверка: _has_cycle(is_a) == False; после add цикла — InvariantError.
Метрика: M-DAG_isa = 1.0
Связь:   монография §5 (иерархия = ОАГ с одинаковым id связи)

--------------------------------------------------------------------------------
T-MATH-03  FOLLOW — ОАГ эпизодов личной истории
--------------------------------------------------------------------------------
Цель:    факты H, связанные FOLLOW, образуют DAG.
Проверка: _has_cycle(follow) == False
Метрика: M-DAG_follow = 1.0
Связь:   монография §5 (эпизод = иерархия по FOLLOW)

--------------------------------------------------------------------------------
T-MATH-04  Гетерархия vs иерархия (отношение включения)
--------------------------------------------------------------------------------
Цель:    Hierarchy ⊆ Heterarchy; Episode ⊆ Hierarchy (по Type-меткам списков).
Проверка на синтетическом графе:
  - список Type=Hierarchy: все рёбра одного id, ацикличен, связен
  - список Type=Heterarchy: связный подграф без требования единого id
  - Episode: Type=Episode + FOLLOW-DAG
Метрика: M-HET = 1 если диаграмма Эйлера-Венна (§5, рис.12) соблюдена
         на тестовых фикстурах; иначе 0

--------------------------------------------------------------------------------
T-MATH-05  Разбиение R по модальностям (привязка символов)
--------------------------------------------------------------------------------
Цель:    для s∈S множества R_i по модальностям попарно дизъюнктны.
Проверка: modality_partition_ok(); негатив — shared token в TEXT и AUDIO.
Метрика: M-R = 1.0
Связь:   монография §2–3 (symbol grounding)

--------------------------------------------------------------------------------
T-MATH-06  Референциальная целостность ссылок SRef/MRef
--------------------------------------------------------------------------------
Цель:    каждая ссылка в L и в fillерсах N указывает на существующий uid
         правильного kind.
Проверка: validate() / _refs_typed
Метрика: M-REF = 1.0

--------------------------------------------------------------------------------
T-MATH-07  Уникальность имён свойств Pr∪Mt внутри элемента
--------------------------------------------------------------------------------
Цель:    в одном элементе нет двух свойств с одинаковым name.
Метрика: входит в M-INV

--------------------------------------------------------------------------------
T-MATH-08  Гиперсвязь N согласована с шаблоном T
--------------------------------------------------------------------------------
Цель:    fillers(N) ⊆ roles(T); predicate(N) соответствует T.s*
Проверка: для каждого N: set(fillers.keys()) ⊆ set(T.actants.roles)
          валентность |fillers| ≤ Q шаблона
Метрика: TemplateInstanceValidity = 1.0
Связь:   монография §3 (модель управления предиката)

--------------------------------------------------------------------------------
T-MATH-09  Отображение AH → фактор-граф (well-formedness)
--------------------------------------------------------------------------------
Цель:    двудольность FG: рёбра только variable↔factor; N не в Variables.
Проверка:
  - V = S ∪ {m ∈ C∪P∪H}  (без hypernodes N как RV — аксиома v1 §9.1)
  - F = {f_N} ∪ {f_l} ∪ {f^obs} ∪ {f^prior}
  - ∀N: N.uid ∉ V
  - каждый актант N ∈ V
Метрика: M-FG = 1.0
Связь:   FACTOR_GRAPH_ACTIVATION.md §4

--------------------------------------------------------------------------------
T-MATH-10  Нормировка beliefs
--------------------------------------------------------------------------------
Цель:    после каждого раунда BP: ∀v  b_v(0)+b_v(1)=1, b≥0
Проверка: max_v |b_v(0)+b_v(1)−1| < 1e-6
Метрика: M-BEL
Связь:   §5.2 sum-product

--------------------------------------------------------------------------------
T-MATH-11  Направленность IS-A потенциала
--------------------------------------------------------------------------------
Цель:    φ_IS-A штрафует X_child·(1−X_parent); не симметричен ASSOC.
Метод:   на минимальном графе child→parent:
  - seed только child → b_parent(1) растёт сильнее, чем при seed parent→child
    (асимметрия обобщения)
  - замена φ на симметричный ASSOC ломает тест (regression guard)
Метрика: M-ISA = 1 если
         b_parent | seed(child)  >  b_child | seed(parent) + margin (margin≥0.05)
Связь:   §4.2.B; кейс «собака» §8 монографии

--------------------------------------------------------------------------------
T-MATH-12  Совместное распределение факторизуется заявленным образом
--------------------------------------------------------------------------------
Цель:    на малом дереве (без циклов) loopy BP ≡ exact marginals.
Метод:  построить дерево IS-A + 1 N; сравнить BP beliefs с brute-force
        ∑_{X\{v}} ∏_a f_a  (полный перебор 2^{|V|}, |V|≤12)
Метрика: max_v |b_BP − b_exact| < 1e-4
Связь:   §4.3 P(X) ∝ ∏ f

--------------------------------------------------------------------------------
T-MATH-13  Prior как замена затухания g
--------------------------------------------------------------------------------
Цель:    без f^obs после нескольких тактов E_v[b_v(1)] мала (режим ε).
Проверка: seed → 8 тактов без evidence → mean(b(1)) < t/2
Метрика: M-PRI = 1 при выполнении порога
Связь:   §4.2.D, §6 таблица g→prior

--------------------------------------------------------------------------------
T-MATH-14  Evidence-фактор поднимает маргинал seed
--------------------------------------------------------------------------------
Цель:    f^obs с λ увеличивает b_seed(1) относительно baseline без obs.
Проверка: b_seed(1 | λ) − b_seed(1 | λ=0) ≥ Δ_min (Δ_min=0.2 при λ≥3)
Связь:   §4.2.C

--------------------------------------------------------------------------------
T-MATH-15  Hebb / θ-обновление с clip
--------------------------------------------------------------------------------
Цель:    w ← clip(w + η·1[b_e1·b_e2>τ_H], 0, 1); α_N аналогично.
Проверка:
  - при совместной активации w не убывает
  - w всегда ∈ [0,1]
  - при b-произведении < τ_H вес не растёт
Метрика: M-HEB
Связь:   §7; монография §8 (актуализация w)

--------------------------------------------------------------------------------
T-ARCH-01  Perception не пишет в AH
--------------------------------------------------------------------------------
Цель:    Perception → FactCandidate / seeds; мутации только через DSL/Ops.
Метод:  mock Perception; assert store fingerprint неизменен до Transform.
Метрика: M-BND += violation count
Связь:   INTERFACES.md граница

--------------------------------------------------------------------------------
T-ARCH-02  Transform пишет только через операции DSL
--------------------------------------------------------------------------------
Цель:    нет прямых ah.C.add / ah.L[...] вне store API.
Метод:  static grep / audit hooks на запрещённые паттерны в perception/
        dialogue LLM path
Метрика: M-BND

--------------------------------------------------------------------------------
T-ARCH-03  AnswerBuilder использует только WM∪Trace (метрика M2)
--------------------------------------------------------------------------------
Цель:    ответ не содержит фактов/UID вне Trace (и инцидентных N).
Метод:  ask("Кто такой заяц?"); извлечь UID из ответа/trace;
        assert set(answer_uids) ⊆ set(Trace) ∪ WM_neighbors
Метрика: M-TR = |answer_uids ∩ Trace| / |answer_uids|
         PASS: M-TR ≥ 0.95; M-LLM = 1 − (#hallucinated_spans)/#spans
Связь:   FACTOR_GRAPH §5.5; INTERFACES «факты только из графа (M2)»

--------------------------------------------------------------------------------
T-ARCH-04  БЯМ не источник маргиналов
--------------------------------------------------------------------------------
Цель:    после ask beliefs зависят от BP+evidence seeds, не от текста NLG.
Метод:  два NLG-бэкенда с разным wording → идентичные b_v и Trace UID
        (при фиксированном Perception seeds)
Метрика: M-LLM; KL(b_A || b_B) < 1e-9

--------------------------------------------------------------------------------
T-ARCH-05  Контур Text→Perc→Xform→Ops→AH→Ign→WM→Ans
--------------------------------------------------------------------------------
Цель:    каждый шаг контракта вызывается ровно в порядке INTERFACES mermaid.
Метод:  instrumented Agent.step_message; проверить порядок событий.
Метрика: PipelineOrderOK ∈ {0,1}

--------------------------------------------------------------------------------
T-ARCH-06  GC / TTL (M3)
--------------------------------------------------------------------------------
Цель:    узел age < TTL не удаляется; orphan age ≥ TTL удаляется;
         связанные live-узлы сохраняются.
Проверка: как test_gc_*; расширить — не удалять N с w>0 и живыми актантами
Метрика: M-GC = 1
Связь:   HYPERPARAMS TTL=32; INTERFACES M3

--------------------------------------------------------------------------------
T-ARCH-07  Разделение variable / factor в экспорте графа
--------------------------------------------------------------------------------
Цель:    UI/dump помечает N как factor, s/m как variable (не смешивать).
Проверка: graph_export metadata kind ∈ {variable, factor}
Метрика: VisualModelOK ∈ {0,1}
Связь:   FACTOR_GRAPH §10.4

--------------------------------------------------------------------------------
T-ARCH-08  Непрерывный диалоговый цикл (траектория WM)
--------------------------------------------------------------------------------
Цель:    ingest → ask сохраняет влияние предыдущего WM (non-empty traces).
Проверка: step_message факт; step_message вопрос → traces непусты
Связь:   монография §8 (контекст / краткосрочная память)

--------------------------------------------------------------------------------
T-ARCH-09  Три типа ЕЯ-воздействий
--------------------------------------------------------------------------------
Цель:    классификация: факт / вопрос / команда (монография §8).
Проверка:
  - факт → created_n ≥ 1
  - вопрос → answer.source ∈ {graph, wm}
  - команда (если реализовано) → не пишет ложный факт без ingest
Метрика: SpeechActRoutingAccuracy ≥ 0.9 на размеченном мини-наборе

3. АЛГОРИТМИЧЕСКИЕ ТЕСТЫ (BP, сложность, устойчивость, ignition)

--------------------------------------------------------------------------------
T-ALGO-01  Определение такта = k раундов damped BP
--------------------------------------------------------------------------------
Цель:    IgnitionEngine.tick выполняет ровно k раундов MP (k=fg_rounds).
Проверка: счётчик rounds == k; damping применяется
          m ← (1−δ)m_new + δ m_old
Связь:   §5.3

--------------------------------------------------------------------------------
T-ALGO-02  Сходимость сообщений (residual)
--------------------------------------------------------------------------------
Цель:    на фиксированном графе residual r_τ = max |m^{τ}-m^{τ−1}| убывает
         или выходит на плато с damping.
Проверка: после k_max раундов r ≤ δ_conv (δ_conv=1e-3) ИЛИ
          не растёт монотонно >3 шага подряд без damping-guard
Метрика: M-CONV

--------------------------------------------------------------------------------
T-ALGO-03  Бюджет такта (latency)
--------------------------------------------------------------------------------
Цель:    один tick на encyclopedia (~1000 узлов) < 500 ms.
Метод:  time.perf_counter; p95 по 20 прогонам
Метрика: M-LAT = p95_ms; PASS < 500
Связь:   HYPERPARAMS / Senior NFR

--------------------------------------------------------------------------------
T-ALGO-04  Асимптотика tick
--------------------------------------------------------------------------------
Цель:    время такта ~ O(|V| + |F| + Σ_a |∂a| · 2^{|∂a|-1}) для binary sum-product
Метод:  синтетические графы размеров N∈{250,500,1000,2000};
        линейная регрессия time ~ a·size; R² ≥ 0.9 при ограниченной
        валентности факторов
Метрика: M-ASY (флаг PASS/FAIL + slope)

--------------------------------------------------------------------------------
T-ALGO-05  Размер фокуса WM (разреженность GWT)
--------------------------------------------------------------------------------
Цель:    после seed на энциклопедии |WM| не вырождается в 0 и не в |V|.
Проверка: 5 ≤ |WM| ≤ 80 при t=0.55, N≈1000, 1–2 seeds
Метрика: M-WM
Связь:   HYPERPARAMS обоснование t; GWT Baars / монография §8

--------------------------------------------------------------------------------
T-ALGO-06  Глубина распространения активации (dog / rabbit)
--------------------------------------------------------------------------------
Цель:    за ≤8 тактов активность доходит до обобщения (IS-A вверх)
         и/или частной модели.
Проверка: hist содержит M_DOG|M_REX|DOG (dog); для rabbit — M_ANIMAL/BEAST
Метрика: M-PROP = max depth по IS-A от seed до активированного предка
         PASS: M-PROP ≥ 2

--------------------------------------------------------------------------------
T-ALGO-07  Pacemaker ν
--------------------------------------------------------------------------------
Цель:    при ν=0 и без входа — коллапс активности (mean b→0);
         при ν=1/8 — слабая ненулевая подпитка без размытия фокуса.
Проверка: калибровочный сценарий HYPERPARAMS «План калибровки» п.5
Метрика: CollapseRatio = mean_b(ν=0)/mean_b(ν>0) < 0.3

--------------------------------------------------------------------------------
T-ALGO-08  Чувствительность к гиперпараметрам (sanity калибровки)
--------------------------------------------------------------------------------
Цель:    качественные эффекты из HYPERPARAMS:
  ↑λ_decay/prior → быстрее гаснет WM
  ↓t → |WM| растёт
  ↑η → быстрее рост w при коактивации
Метод:  A/B на одном seed; проверить направление эффекта (не абсолют)
Метрика: HyperparamDirectionScore = (#верных направлений)/3; PASS = 1.0

--------------------------------------------------------------------------------
T-ALGO-09  Численная устойчивость лог-домена
--------------------------------------------------------------------------------
Цель:    BP не даёт NaN/Inf на графе |V|≥1000 при κ,λ из таблицы §12.
Проверка: после tick все b finite; messages finite
Метрика: NumericStable ∈ {0,1}

--------------------------------------------------------------------------------
T-ALGO-10  Max-product traceback (опционально QA-режим)
--------------------------------------------------------------------------------
Цель:    режим MAP даёт цепочку факторов, согласованную с sum-product Trace
         на дереве (Jaccard ≥ 0.5)
Связь:   §5 / §9.4

--------------------------------------------------------------------------------
T-ALGO-11  Сложность GC
--------------------------------------------------------------------------------
Цель:    collect за O(|E|+|L|) без квадратичных сканов по всем парам.
Метод:  профилирование / счётчик посещений элементов ≤ c·(|E|+|L|)
Метрика: GcVisitRatio ≤ 3

5. ФОРМУЛЫ МЕТРИК (кратко)
================================================================================

M-INV  = 1[ validate(AH) succeeds ]

M-TR   = |UID(answer) ∩ Trace| / max(1, |UID(answer)|)     # faithfulness

M-LAT  = percentile_95({ time(tick_i) }_i)                 # ms

M-WM   = |{ v : b_v(1) > t }| after tick

M-PROP = max_{v∈WM} dist_IS-A(seed, v)   (∞ if unreachable → 0 score)

M-BEL  = max_v |b_v(0)+b_v(1)−1|

M-CONV = ||m^{(τ)} − m^{(τ−1)}||_∞

M-EX   = |EXPECTED_FACT_KEYS ∩ extracted| / 8

M-NFR  = 1[ |S|≥150 ∧ graph_size≥1000 ∧ words≥15000 ∧ ∀s R≠∅ ]

Composite SeniorScore (для отчёта защиты):
  SeniorScore =
      0.20·M-INV
    + 0.15·M-FG·M-BEL          (нормировать M-BEL: 1 если <1e-6 else 0)
    + 0.15·M-TR
    + 0.10·M-LLM
    + 0.10·1[M-LAT<500]
    + 0.10·M-PROP_norm         (min(M-PROP/2, 1))
    + 0.10·M-EX
    + 0.10·M-NFR

PASS защиты (рекомендация): SeniorScore ≥ 0.85 и все hard-gates:
  M-INV=1, M-DAG=1, M-BND=0 violations, M-LAT<500, M-TR≥0.95
