# Пояснительная записка

**Система ассоциативно-гетерархической памяти (АГ-память) с фактор-графовой активацией**

Документ описывает архитектуру реализации, обоснование предметной области, выбранные гиперпараметры и функции, результаты пяти метрик раздела 7 постановки, а также состав корпуса и дампа графа. Объём — в пределах 15 страниц машинописного текста. Полные логи и сериализации вынесены в файлы каталога `docs/submission/`.

---

## 1. Цель и постановка

Работа реализует контур **текст → восприятие → граф АГ-памяти → активация → ответ с трассой UID**. Ответ строится из рабочей памяти и доказательной трассы, а не из свободной генерации большой языковой модели (БЯМ). БЯМ допускается только на границе восприятия (извлечение ролей) и в контрольном агенте Vanilla RAG.

Контрольный агент — **Vanilla RAG**: разбиение того же корпуса на фрагменты, TF-IDF (или n-граммный косинус на стенде), затем извлечение или вызов БЯМ. У RAG нет гиперграфа, ролей актантов и UID-трассы; по постановке M4 его ExplainScore по трассе равен нулю.

Пять метрик раздела 7:

| Метрика | Смысл | Скаляр |
|---------|--------|--------|
| **M1** | Извлечение ролей SUBJECT / OBJECT / LOCATION | нормированный взвешенный F1 |
| **M2** | ExplainScore: верный ответ × (глубина / d_max) × полнота трассы | среднее по корпусу QA |
| **M3** | Доля удалённых сирот при GC | \(1 - N_{\text{after}}/N_{\text{before}}\) |
| **M4** | Сравнение с RAG: \(\Delta_{\text{explain}} = E_{\text{AH}}-E_{\text{RAG}}\), \(\Delta_{\text{hall}} = H_{\text{RAG}}-H_{\text{AH}}\) | два независимых дельта; для итога — среднее |
| **M5** | Устойчивость SLM относительно LLM: \(F1_{\text{AH}}^{\text{SLM}}/F1_{\text{RAG}}^{\text{SLM}} - F1_{\text{AH}}^{\text{LLM}}/F1_{\text{RAG}}^{\text{LLM}}\) | robustness_gain |

## 2. Предметная область и обоснование выбора

### 2.1. Канонический пример монографии

Предметная область демонстрации — **короткий энциклопедический текст о зайце** (эталон монографии Р. В. Душкина об ассоциативно-гетерархической памяти). Текст фиксирован в фикстуре `src/ah_memory/examples/rabbit.py` и воспроизведён в `docs/submission/corpus.txt`.

Выбор области обоснован не «зоологией», а **структурным покрытием механизмов АГ-памяти** на минимальном корпусе:

1. **Таксономия (иерархия IS-A).** «Заяц — зверёк — животное» даёт ориентированный ациклический фрагмент иерархии, который должен переживать активацию вверх по IS-A и попадать в трассу ответа «кто такой заяц».
2. **Мультиарные факты (гетерархия N).** Обитание (субъект + локации), обладание частями тела, окраска с временной ролью TIME — это гиперрёбра, а не пары «слово–слово». Именно они отличают АГ-память от мешка чанков RAG.
3. **Причина и следствие.** «Сильные задние лапы → бегает быстро» проверяет, что ответ «почему» опирается на фактор с ролью причины, а не на пересказ соседнего предложения.
4. **Отказ при отсутствии знания.** Вопрос про «вес короля зайцев на Луне» отсутствует в корпусе: АГ-агент должен ответить «неизвестно», RAG на БЯМ склонен достраивать ответ общими знаниями (галлюцинация по M4).
5. **Нейтральность кода.** Имена сущностей и предикаты живут только в фикстурах и бенчмарках. Производственный контур не ветвится по словам «заяц», «лес», «шерсть»: нормализация отношений открытая, gate проверяет заземление ролей в тексте, а не словари предметной области.

На том же графе считаются доменные инварианты: попадание 8 эталонных ключей фактов (`IS:HARE:BEAST`, `LIVE_IN:HARE`, `HAVE:HARE:HIND_LEG`, `RUN:HARE`, `HAVE:HARE:EAR`, `HAVE:HARE:TAIL`, `BE_COLORED:FUR:BROWN`, `BE_COLORED:FUR:WHITE`) и синтаксический ответ `answer_who(M_HARE)`.

### 2.2. Стенд открытого челленджа (M1–M4 offline)

Чтобы не смешивать оценку архитектуры с одним русским абзацем, метрики M2–M4 дополнительно прогоняются на **фиксированных JSONL-корпусах** (`benchmarks/challenge/`): 100 англоязычных ролевых реплик (логистика, медицина, ПО, полевые исследования, искусство; варианты clean / typo / inversion / ellipsis) и 20 QA-кейсов с эталонной цепочкой ссылок длины 1…6. Эти тексты нарочно **не привязаны к зайцу**: они проверяют, что активация и GC работают на произвольных UID.

Итого: предметная область защиты — заяц (объяснимость для человека и золотой набор M4); предметная область стенда — открытые роли и синтетические цепочки (воспроизводимость M1–M3 и честное сравнение с RAG без подгонки под один текст).

## 3. Архитектура

### 3.1. Кортеж АГ-памяти

Память — кортеж \(\mathrm{AH}=\langle S,C,P,H,L\rangle\):

- **S** — словарь абстрактных символов (ярлыки, словоформы, модальности). Карточка «заяц» сама по себе не факт.
- **C / P / H** — три равноправные гиперсети второго порядка: общее, частное, эпизоды. Элемент лежит ровно в одной полке.
- **L** — бинарные связи (ASSOC, IS-A, FOLLOW, …) между ссылками на элементы, в том числе из разных полок.
- **N** (в реализации — семантические факторы) — n-арные факты с ролями актантов.

Инварианты: уникальность UID, ацикличность IS-A и FOLLOW, ссылочная целостность. Мутации графа идут только через DSL / `AHStore`, не из Perception.

### 3.2. Конвейер

```text
текст
  → Perception (БЯМ или seeds) → FactCandidate + seed UID
  → gate (заземление ролей в тексте, схема JSON)
  → Transform (нормализация отношения, Event, Factor)
  → AHStore ⟨S,C,P,H,L⟩ + RelationRegistry
  → immutable FactorGraph
  → persistent BPState (сообщения, beliefs, evidence)
  → Activation / WM = {v | x_v > t}
  → AnswerBuilder / DSL  (ответ только из WM и трассы)
```

Граница модулей: Perception **не пишет** в граф. Transform применяет кандидаты. Ignition / belief propagation не вызывают БЯМ. Ответ не генерируется «из модели»: строится интерпретатором поверх возбуждённых узлов (`answer_who`, слоты location/color/cause и т.п.).

Открытая семантика (аддитивный слой): сырое имя отношения → `RelationNormalizer` → реестр с `RelationProperties` → n-арный фактор → параметры (`fixed | rules | embedding projection`) → `ActivationEngine` без ветвления по ярлыку предиката. Известные legacy-предикаты по-прежнему могут порождать гиперсвязь N; неизвестные отношения не требуют правки исходного кода.

### 3.3. Фактор-граф вместо тактового «фокуса»

Скалярная возбудимость \(x_e\in[0,1]\) монографии сохранена для UI, но вывод идёт через фактор-граф:

\[
m(f\to v)=\mathrm{Potential}_f(\text{входящие сообщения},\theta_f),\quad
z_v=\sum_f \mathrm{contrib}(f\to v),\quad
x_v^{t+1}=G(x_v^t,z_v^t,e_v^t,\theta).
\]

Belief и активация разделены: BP формирует \(z_v\), затем `ActivationFunction` обновляет \(x\). Точная n-арная свёртка перечисляет \(2^{\mathrm{arity}-1}\) конфигураций; для больших факторов режим `approximate` выбирается явно, `auto` переключается по `exact_max_arity`.

Рабочая память: \(\mathrm{WM}=\{v\mid x_v>t\}\). Трасса: рёбра и факторы с вкладом выше \(\varepsilon_{\mathrm{tr}}\). ExplainScore (M2) обнуляется, если эталонная цепочка UID не является подпоследовательностью фактической трассы.

### 3.4. Контрольный агент

`VanillaRAG` режет корпус на чанки, ранжирует TF-IDF, отвечает извлечением или вызовом DeepSeek. Поле `trace_uids` всегда пусто. На стенде челленджа RAG — косинус n-грамм + эвристический ответ по маркерам `follows` / `is a` / `causes` в тексте документа (без графа).

## 4. Гиперпараметры и функции

Значения — стартовые точки из `docs/HYPERPARAMS.md` и `config.yaml:experiment`, а не утверждение о глобальном оптимуме. Калибровка на защите: увеличить \(\lambda\) (быстрее гаснет WM), уменьшить \(t\) (шире фокус), выключить pacemaker.

### 4.1. Ignition (монография §8)

| Имя | Обозначение | Значение | Зачем |
|-----|-------------|----------|--------|
| TTL | \(L\) | 32 такта | Новый узел успевает получить связь; GC в TTL живое не трогает (M3) |
| Затухание | \(g(x)=x\,e^{-\lambda\Delta t}\) | \(\lambda=0{,}15\), \(\Delta t=1\) | Полураспад ~4,6 такта: контекст держится, без входа гаснет |
| Порог WM | \(t\) | 0,55 | Отсекает шум при \(w\in[0{,}3;0{,}8]\) |
| Хебб | \(h\): \(w\leftarrow\mathrm{clip}(w+\eta x_{\mathrm{out}}x_{\mathrm{in}},0,1)\) | \(\eta=0{,}05\) | Медленная актуализация, \(w\in[0,1]\) |
| Pacemaker | \(\nu\) | 1 импульс / 8 тактов | Живой фокус между репликами; \(\nu=0\) → коллапс без входа |
| Seed | \(\delta\) | 0,8 | Сенсорная подпитка UID из Perception |
| Старт \(w\) | — | 0,5 | Нейтральный вес новой связи |

Активация ребра в постановке: \(f(z)=\sigma(z)=1/(1+e^{-z})\), выход на ребро \(f\cdot w\).

### 4.2. Belief propagation

| Параметр | Поле | Значение |
|----------|------|----------|
| Жёсткость потенциала | `fg_kappa` | 2,0 |
| Сила evidence | `fg_lambda` | 3,0 |
| Prior | `fg_epsilon` | 0,05 |
| Damping | `fg_damp` | 0,4 |
| Раунды BP на такт | `fg_rounds` | 2 |
| Порог трассы | `fg_trace_eps` | \(10^{-3}\) |
| Порог Хебба FG | `fg_hebb_tau` | 0,15 (Hebb по умолчанию выключен) |

### 4.3. ExperimentConfig (`config.yaml`)

| Группа | Выбор и смысл |
|--------|----------------|
| `activation.type` | **linear**: \(G\) линейна по \(z\) и evidence; альтернативы sigmoid / relu для сетки |
| `alpha, beta, gamma` | 1,0 / 1,0 / 1,0 — равный вклад состояния, входа и evidence |
| `decay` | 0,1 — затухание активации между тактами эксперимента |
| `eta` (activation) | 0,5 — масштаб обновления \(x\) |
| `is_a_up / is_a_down` | 0,9 / 0,2 — иерархия проводится вверх сильнее, чем вниз |
| `follow_forward / backward` | 0,8 / 0,1 — эпизоды читаются вперёд |
| `association` | 0,4 — слабее направленной семантики |
| `bind` | 0,8 — связка актантов фактора |
| `hypernode_mode` | **soft_and** — мягкая конъюнкция участников гиперребра (не жёсткий AND) |
| `max_ticks` | 20 (агент QA на зайце: 6 тактов — короткий фокус) |
| `threshold` | 0,7 — порог экспериментального WM (отдельный от ignition \(t=0{,}55\)) |
| `damping` | 0,4 — согласован с `fg_damp` |
| `factor_evaluation` | **auto**, `exact_max_arity=12` |
| `contribution_mode` | **delta** — вклад фактора как приращение, не counterfactual logit |
| `competition` | выключена (`none`) — на малом графе зайца конкуренция не нужна |

Open semantics: `normalization_mode=normalized`, порог сходства эмбеддингов 0,55. Identity: слияние упоминаний при `safety_threshold=0,94`. Случайность эксперимента: `random_seed=42`.

### 4.4. Функции, зафиксированные в коде

- \(g,h,f\) — в `HyperParams` (`src/ah_memory/hyperparams.py`).
- Потенциалы факторов — `src/ah_memory/potentials.py` (IS-A направленный и мягкий, ASSOC симметричный, semantic — из свойств отношения).
- GC: `collect(store, HyperParams(ttl=…))` удаляет сирот после TTL, не трогая живые компоненты (проверка `false_live_deletes`).
- Gate восприятия: confidence ≥ 0,5 и lemma-заземление ролей; без семантических «угадываний» по домену.

## 8. Выводы

1. Архитектура разделяет восприятие, мутацию AH, вероятностную активацию и построение ответа; БЯМ не является памятью.

3. Гиперпараметры ignition и BP — стартовые из постановки §8; `config.yaml` фиксирует linear activation, soft_and, направленные веса IS-A / FOLLOW.
