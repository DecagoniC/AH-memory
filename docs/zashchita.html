Не начинайте с зайца. Сначала покажите, что модель не пишет ответ из головы, а получает сжатый список фактов из памяти.

Построение графа · 1

Текст сначала разбирается, в граф ещё не пишется

  1. Perception. Модель (DeepSeek, GigaChat или Ollama) возвращает JSON: предикат, роли актантов, цитату raw_span, уверенность. Это кандидаты, не факты памяти.
  2. Роли протокола. Допускаются только SUBJECT, OBJECT, LOCATION, TIME, CAUSE, TOOL, MATERIAL, PURPOSE, HOW-TO, WITH. Прочие поля отбрасываются схемой, а не «догадкой про зайца».
  3. Семена. Даже без полного факта слой отмечает, о каких сущностях речь: seed_tokens. Они понадобятся как точки входа при вопросе.
Фраза: «Заяц обитает на лугу» Кандидат: LIVE_IN · SUBJECT=заяц · LOCATION=луг · raw_span=«Заяц обитает на лугу»

Подчеркните: Perception не вызывает Store. Если JSON кривой — ремонт по схеме, не семантическое угадывание.

Построение графа · 2

Гейт пускает только то, что есть в исходном тексте

Проходит

  • Роль заземлена в фразе (лемма / вхождение).
  • Уверенность не ниже порога (0,5).
  • UID роли не слишком широкий («всё», «они»).

Не проходит

  • Сущность, которой в тексте нет: модель додумала.
  • Роль вне протокола.
  • Кандидат без двух актантов: фактор не из чего собрать.

Гейт — сито, не вторая модель. Он не добавляет знаний и не уравнивает 8b с DeepSeek.

Построение графа · 3

Transform записывает событие и n-арный фактор

  1. Символы. Для каждой роли: абстрактный символ в S и карточка второго порядка (ярлык «заяц», «луг»).
  2. Отношение. Сырое имя нормализуется в каноническую метку реестра. Неизвестный предикат регистрируется, код под него не пишется.
  3. Event + Factor. Появляется событие с ролями-ссылками и семантический фактор N. Это гиперребро, не чанк текста.
  4. Связки. Между актантами одного факта ставится ASSOC — микротема для последующего воспламенения.

Мутации идут только через Store / DSL. Perception в граф не пишет. Дубликаты того же предиката и тех же ролей не плодятся.

Построение графа · 4

После записи в памяти лежит структура, а не абзац

AH = ⟨S, C, P, H, L⟩ + факторы N S символы и словоформы «заяц», «луг» C/P/H общее / частное / эпизоды карточка на одной полке L бинарные связи IS-A, FOLLOW, ASSOC N n-арный факт LIVE_IN(SUBJECT=заяц, LOCATION=луг) UID стабильный адрес узла по нему потом строится трасса

Корпус RAG при этом существует отдельно: те же документы режутся на чанки для контроля. У чанка нет UID и нет ролей.

Точки входа

Вопрос не записывается. Он ищет якоря в уже построенном графе

  1. Сброс. Сообщения belief propagation и рабочая память прошлого вопроса гасятся. Сам граф не трогается.
  2. Сначала упоминания. В формулировке ищутся самые длинные точные имена сущностей из S. «Заяц» бьёт в UID зайца, а не в случайный токен.
  3. Затем семена Perception. Если точного упоминания нет, берутся seed_tokens и словоформы. Не больше 16 якорей.
  4. План запроса. Среди соседних фактов якоря выбирается одна связь и один слот ответа (кто / что / где). Победившие факторы получают маску 1, остальные — 0.

Писать вопрос как факт нельзя: иначе память засоряется своей же формулировкой.

Это one-hop: соседи якоря, не цепочка A→B→C в планировщике. Длинные hop идут уже через такты воспламенения.

Воспламенение

Якоря получают evidence, такт несёт активацию по факторам

  1. Семена. Каждому якорю кладётся evidence δ = 0,8. Это старт фокуса, не новый факт.
  2. Такты BP. Сообщения переменная → фактор и фактор → переменная. Потенциал фактора смотрит на роли и маску плана.
  3. Активация. Скаляр x узла обновляется из вклада факторов, затухает с λ = 0,15. Полураспад ≈ 4,6 такта.
  4. Рабочая память. WM = { узлы с x > t }, t = 0,55. Ниже порога — шум, в ответ не идёт.
  5. Трасса. UID, которые вспыхнули по тактам, плюс факторы с вкладом выше ε. Это доказательство, не похожесть чанка.

Структура Store здесь не меняется. Ignition не вызывает языковую модель.

Контекст модели

В промпт идёт сжатый список фактов, а не UID и не весь граф

Как отбирается

Ранжировщик считает релевантность фактора к вопросу: лексика формулировки, активация узлов, маска плана, поддержка соседей. В промпт — до 12 фактов с ненулевым счётом. Сырые UID в текст не попадают, только человекочитаемые ярлыки и цитаты.

Закрытый мир

Системный блок говорит: опирайся только на этот список; не добавляй места, даты, числа и связи, которых нет; если факта нет — ответь ровно «неизвестно». Общие знания запрещены. Если компактный список пуст, запасной путь — строка декодера «Активировано: …».

Пример

От фразы до того, что видит модель

Запись: «Заяц обитает на лугу» → LIVE_IN(SUBJECT=заяц, LOCATION=луг) в графе Вопрос: «Где обитает заяц?» → якорь: заяц → воспламенение: заяц, луг, фактор LIVE_IN → декодер читает слот LOCATION → «луг» Контекст модели: [Контекст из АГ-памяти — единственный источник фактов] • обитает: субъект заяц, место луг Пользовательская реплика модели: «Где обитает заяц?» Ответ модели должен перефразировать только этот список.

Если спросить про массу короля зайцев на Луне, якорь может вспыхнуть, но нужного фактора нет — корректный контекст пуст по сути, ответ «неизвестно».

M1 · суть теста

Одни и те же короткие фразы, две разборки ролей

Протокол

12 шаблонных предложений стенда инцидента Hugging Face. Эталон — тройки SUBJECT / OBJECT / LOCATION. Вес субъекта и объекта = 2, локации = 1. Считается нормированный взвешенный F1. Порог Middle из постановки: ≥ 0,6.

Два режима

AH-gated — после гейта: в счёт идут только роли, заземлённые в тексте. Без гейта — сырой JSON модели. Здесь нет общего графа и нет ответа на вопрос: измеряется только парсер на границе.

M1 · график

Класс модели важнее гейта

Синие столбцы — AH-gated F1. Модель предложила роли, гейт оставил только те, что встречаются в исходной фразе. Это тот разбор, который реально идёт в Transform.

Серые столбцы — F1 без гейта. Та же модель, тот же текст, без сита. На коротких шаблонах серый столбец чуть выше: гейт отбрасывает лишнее, эталону это не помогает.

Вертикаль 0…1 — нормированный взвешенный F1. Линия 0,6 на шкале — порог Middle. n = 12.

M2 · суть теста

Верный ответ считается только вместе с полной трассой

Офлайн-стенд: 20 вопросов с эталонной цепочкой UID длины 1…6. Модель чата не вызывается. Срабатывает только воспламенение и декодер.

ExplainScore = (1/N) Σ 1_верный · (глубина / 6) · 1_трасса_полная

Если ответ угадан, но в трассе нет эталонной подпоследовательности UID — вклад нулевой. Это проверка точек входа и тактов, не беглости текста.

M2 · график

На глубине 1–4 трасса доходит, на 5–6 — нет

Синие — доля вопросов этой глубины, где ответ верен и трасса UID полная. На d = 1…4 это все кейсы (4, 3, 3 и 3 вопроса).

Серые — кейсы, где активация не дошла до эталонного UID. Все 3 вопроса глубины 5 и все 4 вопросы глубины 6.

Итоговый ExplainScore = 0,26: 13 из 20 с полной трассой, вклад взвешен глубиной. Провал d = 5–6 — затухание и порог WM, не отсутствие механизма.

M3 · суть и график

Сборка мусора снимает сирот и не трогает живое

Серый столбец — 200 сирот до GC. Узлы без связи, TTL = 50 тактов.

Зелёный столбец — сироты после GC. Ноль. Живые LIVE / M_LIVE и их связь сохранены, ложных удалений нет.

Метрика постановки: доля собранных сирот = 1 − N_после / N_до = 1,00. Это санитарный инвариант памяти, не качество парсера.

M4 · суть теста

Тот же корпус: граф с трассой против чанков без UID

АГ-память

Вопрос → якоря → воспламенение → ответ из WM. ExplainScore ненулевой, только если ответ верен и трасса содержит эталонные UID.

Vanilla RAG

Те же документы режутся на фрагменты. Поиск TF-IDF или FAISS, затем извлечение или пересказ моделью. Поля трассы UID нет, поэтому ExplainScore RAG по постановке всегда 0.

Δ объяснимости = E_AH − E_RAG. Δ галлюцинаций = H_RAG − H_AH. Два независимых золота: заяц (n = 6) и инцидент Hugging Face (n = 6, граф пересобирается на каждый бэкенд).

M4 · график, эталон «заяц»

На монографии гипотеза закрыта целиком

Синие — АГ-память. ExplainScore 0,67: ответы с трассой. Галлюцинации 0: на лунном короле зайцев система сказала «неизвестно».

Красные — Vanilla RAG с DeepSeek. ExplainScore 0: нет UID. Галлюцинации 0,50: генератор дописывает массу и энциклопедию сверх фрагмента.

Ось 0…1. Левая пара — объяснимость (больше лучше). Правая — доля галлюцинаций (меньше лучше).

M4 · график, инцидент Hugging Face

После пересборки графа Δ объяснимости = 0,25 против любого RAG

Зелёные — Δ объяснимости. 0,25 на всех четырёх бэкендах, потому что граф и агент собираются заново: след активации прошлого RAG больше не портит AH.

Красные — доля галлюцинаций RAG. Extractive цитирует чанк (0,33). Чат-модели на закрытом промпте всё равно дописывают (1,0). Галлюцинации AH на этом стенде 0,17 — ловушка с секретным кодом, где отказ не случился.

Ось 0…1. n = 6 вопросов. ExplainScore RAG = 0 по контракту метрики.

M5 · суть и график

Типизация ролей не компенсирует слабость 8b

Формула: RobustnessGain = (F1_AH_SLM / F1_без_гейта_SLM) − (F1_AH_LLM / F1_без_гейта_LLM). Ожидание постановки: плюс, если гейт сильнее помогает маленькой модели.

Против GigaChat: −0,080. Отвергаем гипотезу: 8b выигрывает от гейта меньше, чем коммерческая модель.

Против DeepSeek: +0,104. Плюс из-за просадки gated F1 у DeepSeek (0,605 против 0,781 без гейта), а не потому что 8b вырос. Честный reject по GigaChat — валидный исход.

Вывод

Что следует из контура и из чисел

Контур работает как заявлено

  • Текст становится гиперрёбрами с ролями, не мешком чанков.
  • Точки входа — якоря в вопросе, не запись вопроса в память.
  • Воспламенение зажигает WM; в модель идёт сжатый закрытый список фактов.
  • M3 = 1,0. M4: Δ объяснимости > 0, потому что у RAG нет трассы UID.

Где предел

  • Итоговый F1 следует за классом парсера: 8b не дотягивает до 0,6, коммерческие модели дотягивают.
  • Гейт не лечит слабый JSON. M5 отвергнут.
  • Длинные цепи d = 5–6 гаснут. На ловушках отказ не всегда срабатывает.
  • Когда обе модели видят один граф, ответы уравниваются: разрыв был во входе, не в «уме».

Память хранит доказательство. Модель только разбирает текст на входе и пересказывает выданный контекст.
